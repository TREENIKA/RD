Activity 4: The Secret Knock

SQL Injection Challenge!

Imagine you have a secret knock to get into a club, but what if someone figures out a "master knock" that works for everyone? That's kind of what SQL Injection is! You'll try to trick a pretend login screen to let you in without the right password. This shows how important it is for websites to be built securely! (No real websites or data are involved, just a fun demo!)

Most websites store your info (like usernames and passwords) in a database — think of it like a giant spreadsheet locked in a back room.

When you log in, the website asks the database: “Does this username + password match?” It uses a special language called SQL to ask. SQL injection is when a hacker sneaks extra commands into that question to confuse the database.

For example, the injection string ' OR '1'='1 makes the database think: “Is the password correct, OR is 1=1?” Since 1 always equals 1, it always says YES, letting the hacker in!

Real-world impact: SQL injection has been used to steal millions of passwords. Developers prevent it by “sanitizing input” — never trusting data typed by users.

Under the Hood

What the Database Actually Sees

When you log in to a website, it runs a SQL query behind the scenes. Here's what a vulnerable login looks like:

😰 Vulnerable Code

The website blindly pastes your input straight into the SQL query. This is the mistake that lets hackers in.

-- The website builds this query: SELECT * FROM users WHERE username = 'admin' AND password = '[whatever you typed]'

Now type ' OR '1'='1 as the password and watch what happens to the query:

-- Injected version: SELECT * FROM users WHERE username = 'admin' AND password = '' OR '1'='1' -- The database sees this as: -- (password matches) OR (1=1) ← always true! -- Result: LOGGED IN. No password needed.

🛡️ The Safe Version

Secure websites use parameterized queries — the data and the command are kept completely separate. Your input can never become part of the SQL command.

-- Safe: uses a placeholder (?) for input SELECT * FROM users WHERE username = ? AND password = ? -- Even if you type ' OR '1'='1 -- the database treats it as literal text, -- NOT as SQL code. Attack fails. ✓

This is called input sanitization — the #1 defense against SQL injection.

Try These

Real Injection Strings

These are actual payloads security researchers use to test for SQL injection vulnerabilities. Try each one in the lab below.

🧪 Classic Payloads

  • ' OR '1'='1 The classic. Makes the WHERE condition always true.
  • ' OR 1=1 -- The -- comments out the rest of the query. Anything after it is ignored.
  • admin'-- If the username is "admin", this logs in as admin by commenting out the password check entirely.
  • ' OR 'x'='x Works the same as 1=1 — any statement that is always true works.

💣 Real World: The 2008 Heartland Breach

In 2008, a hacker named Albert Gonzalez used SQL injection to break into Heartland Payment Systems. He stole over 130 million credit card numbers from a single company.

The attack worked because Heartland's code trusted user input and put it directly into SQL queries — the exact vulnerability you just exploited in the demo.

Gonzalez was sentenced to 20 years in federal prison. The breach cost Heartland over $140 million in settlements.

One missing parameterized query. $140 million. 20 years.
